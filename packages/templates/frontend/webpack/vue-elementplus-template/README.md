# repository

Phase 0 monorepo foundation: pnpm workspaces, Turborepo, TypeScript,
`@antfu/eslint-config`, Vitest.

## Requirements

- Node.js >= 22 (development and CI use the version in `.node-version`)
- pnpm, via Corepack: `corepack enable`

## Getting started

```bash
corepack enable
pnpm install
pnpm verify        # lint, typecheck, test, build (cached by Turborepo)
```

## Commands

| Command                 | What it does                                   |
| ------------------------| ------------------------------------------------|
| `pnpm verify`           | lint + typecheck + test + build for everything |
| `pnpm verify:affected`  | the same, only for projects changed vs. `main` |
| `pnpm dev`              | run every project's `dev` script               |
| `pnpm check:boundaries` | enforce the dependency rules                   |

Single project: `pnpm --filter @acme/example-app <script>` or run the script
inside its directory.

## Layout

```text
apps/       deployable units (never depended upon)
packages/   runtime libraries (named after a capability)
tools/      dev-time configuration (currently: ESLint factory + variants)
docs/       ADRs and guides
scripts/    repository tooling (check-boundaries)
```

`apps/example-app` and `packages/example-lib` are temporary samples that
exercise the dependency graph, caching and affected-only runs. Delete them when
real projects exist.

## Linting

There is no Prettier. Formatting and linting are both handled by
`@antfu/eslint-config`, wrapped in `tools/config-eslint`:

- `tools/config-eslint/node.js` — in use.
- `tools/config-eslint/vue.js`, `react.js`, `uniapp.js` — placeholders, not yet
  validated against a real project. Read the TODO comment at the top of each
  before using it. See [ADR-0002](docs/adr/0002-eslint-antfu.md).

Each app/package points at its variant explicitly in its own
`eslint.config.js` — it does not rely on `@antfu/eslint-config`'s automatic
framework detection, since hoisted dependencies in a pnpm workspace could make
that detection pick the wrong framework.

## Rules in one minute

1. `apps -> packages`, never the reverse, never in a cycle. `tools` is
   dev-only and never depended on by app code at runtime.
2. A package needs two real consumers and a capability name. No `shared` or
   `utils`.
3. New environment variables go in `.env.example` and `turbo.json`.
4. Commits follow Conventional Commits (`feat: ...`, `fix: ...`).

Details: [docs/](docs/README.md).

## Renaming the package scope

The scope `@acme` is a placeholder. From the repository root:

```bash
# Linux
grep -rl "@acme" . --exclude-dir=node_modules --exclude-dir=.git | xargs sed -i 's/@acme/@your-org/g'
# macOS: use  sed -i ''  instead of  sed -i
```

## Troubleshooting

- pnpm reports "Ignored build scripts": run `pnpm approve-builds` and allow `esbuild`.
- CI fails on `--frozen-lockfile`: commit `pnpm-lock.yaml` (generated by the
  first `pnpm install`).
- ESLint reformats a file into a style you don't expect (no semicolons, single
  quotes): that is `@antfu/eslint-config`'s convention, not a bug. See ADR-0002.
